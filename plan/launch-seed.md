# 公開前シード（運営の投稿）— 決定版

正式公開の前に、本番に「運営の投稿」を入れておく。はじめて来た人が空っぽの部屋に入らずにすむように。
確認用の架空データ（seed_demo）とは別物で、こちらは本番に残し続ける本物の投稿。

- コマンド: `python manage.py seed_launch`
- 中身: `backend/common/launch_content/`（文章はすべて手書き。乱数は使わない）
- テスト: `backend/tests/test_seed_launch.py`

---

## 1. 決めたこと（2026-10-12）

| 項目 | 決定 |
|---|---|
| 言語 | 英語中心＋日本語少し（メインの読者は海外の人） |
| アカウント | 役割ごとに 3 つ。名前で運営と分かるよう全員 `NeONChurch` で始める |
| AI の開示 | 3 アカウントの自己紹介に「運営が AI の助けを借りて書いた」と明記。投稿本文には書かない |
| 本番のデモデータ | 消してから入れる（`seed_demo --wipe-only` → `seed_launch`） |
| 架空の一般ユーザー | 作らない。投票・お気に入り・通知も作らない（運営が自分で票を入れたように見せないため） |

### アカウント

| ユーザー名 | 役割 |
|---|---|
| `NeONChurch` | 公式。サイトの案内記事、翻訳プロジェクトの立ち上げ |
| `NeONChurch_Editors` | 編集部。節への「問い」と読み方の投稿、記事、Q&A の質問 |
| `NeONChurch_Guides` | 案内係。読書プラン、Q&A の回答、書の紹介 |

パスワードは作ったときに一度だけ表示する（後から運営として返信できるように）。staff / superuser にはしない。

### 書き方の方針（plan/editorial_seed_comments.md を引き継ぐ）

- 節のスレッドは「編集部の問い」を頭に置き、その下に違う読み方（Traditional / Skeptical / Literary / Ethical / Reception history）を返信で並べる
- 全体は中立、個々の読み方は言い切る。「どちらの見方もある」で締めない
- 架空の信仰体験や、一般の利用者を装った書き方はしない
- 本文の引用は、リポジトリにある本文（KJV・口語訳・文語訳・Brenton・Charles・Mattison・解釈書）と照合して写した
- 立場で答えが割れる Q&A は解決済みにしない。回答の無い質問も少し残す（利用者が最初に答えられる場所）

## 3. 安全のための仕組み

- **二重投入を止める**: 運営の投稿が既にあればエラーで止まる。入れ直すときだけ `--replace`
- **`--replace` は運営の投稿だけ消す**: 一般の人の投稿は残る。ただし運営の投稿に付いた返信・回答・購読は一緒に消える
- **DB に無い箇所は飛ばす**: 本番に入っていない書・章・解釈書を指す投稿は作らず、最後に一覧で出す
- **全部で 1 つの処理**: 途中で落ちたら何も入らない
- **`--dry-run`**: 件数と飛ばす箇所だけ確かめて、DB は元に戻す
- テストで、書いた箇所がすべてリポジトリの本文データに実在することを確かめている

## 4. 本番での流し方（Render）

1. Render のダッシュボード → backend のサービス → 左メニュー「Shell」を開く
2. まず確認だけ: `python manage.py seed_launch --dry-run`
   - 最後に「DB に無い箇所を N 件飛ばしました」と出たら、その一覧を控える（解釈書が未投入なら `import_commentary` を先に）
3. デモデータを消す: `python manage.py seed_demo --wipe-only`
   - 管理者（superuser / staff）以外のユーザーと、その投稿がすべて消える。聖書本文は残る
4. 運営の投稿を入れる: `python manage.py seed_launch`
5. 最後に表示される 3 アカウントのパスワードを控える（二度と表示されない）

## 5. 直したいとき

`backend/common/launch_content/` の文字列を直して push → デプロイ後に `python manage.py seed_launch --replace`。
公開後は、運営の投稿に利用者の返信が付いている可能性があるので、`--replace` の前に返信の有無を確かめること。
