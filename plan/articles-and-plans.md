# 記事（articles）とプラン 設計

編纂書（compilations）を廃止し、**記事**と**プラン**の2機能に作り直す。

編纂書は「節を並べる」作業と「自分の文章を書く」作業が1画面に同居していて、
どちらも中途半端になっていた（自分で書いた文章まで節として扱っていた）。
性質が違うので分ける。

- **記事** — 節を引用しながら自分の文章を書く。1ページ完結。
  gotquestions.org の記事のように、散文の中に引用が埋まっている形。
- **プラン** — 章を書をまたいで並べ、日ごとに自分の文章を添える読書コース。

**記事から作る。** 記事は書く人が1人でも成立するが、プランは読む人が付いて
初めて意味が出る。また、記事で作る「引用を埋め込んで書く」土台を、プランの
日ごとの文章でそのまま使い回せる。

---

## 共通で決まったこと

- **箇所は訳非依存で持つ**（`CanonicalBook` + 章番号 + 節番号）。既存のお気に入り
  （`backend/bookmarks/models.py`）とまったく同じ形なので、お気に入りから引用へ変換なしで繋がる。
- **訳は任意で指定できる。** 指定があればその訳で表示・遷移し、無ければ読む人の訳。
  あえてギリシャ語を指定する、ができる。
- 呼び名は「記事」「プラン」。URL は `/articles` `/plans`。
- 編纂は全削除。`MotifTag` だけ記事のタグとして引き継ぐ。

## 記事

### データ

**Article**
| 項目 | 内容 |
|---|---|
| owner | 書いた人 |
| title | 題 |
| summary | 要約。60〜120字。**公開するときは必須**（下書きなら空でよい） |
| body | 本文。Markdown ＋ 引用の印 |
| visibility | private / unlisted / public |
| tags | `MotifTag` への多対多。**1記事3つまで** |

**ArticleCitation**（引用の索引）
| 項目 | 内容 |
|---|---|
| article | どの記事か |
| canonical_book / chapter_number | 訳非依存の箇所 |
| verse_number_start / verse_number_end | 節の範囲（end は空なら1節だけ） |
| translation | 訳の指定（任意） |
| kind | inline（文中の参照）/ block（引用ブロック） |

**本文（body）が正本で、ArticleCitation はそこから作られる索引。**
記事を保存するたびに本文の印を読み取り、この表を作り直す。
これがあるので「この節を引用した記事」を逆から引ける。

**ArticleComment** — 記事全体に対してのみ。記事の中の節にはコメントを付けない。

### URL

`/articles/[id]` にする。日本語の題からは読めるURL文字列を作れない
（`slugify("断食について")` は空になる）ため、id をそのまま使う。

- `/articles` 一覧（新着順・タグで絞り込み）
- `/articles/new` 新しく書く
- `/articles/[id]` 表示
- `/articles/[id]/edit` 編集
- `/profile/[username]` に記事タブを追加

### 引用の印

| | 書き方 | 表示 |
|---|---|---|
| 文中の参照 | `[[matthew 6:16-18]]` | (マタイ 6:16-18) ← リンク |
| 引用ブロック | `{{matthew 6:16-18}}` | 節の本文 ＋ 出典 |
| 訳の指定 | `{{matthew 6:16-18\|greek}}` | 縦棒のあとに訳 |

- 1節だけなら `matthew 6:16`
- 章まるごと `matthew 6` は**参照だけ可**（引用ブロックにすると長すぎる）
- 印は挿入UIから入るもので、**書く人が手で打つことは想定しない**
- 解決できない印（書き間違い・その訳に無い節）は、本文を出さず控えめに
  「見つかりません」と表示する。記事全体は壊さない

### 編集画面

引用が1記事に10〜20個入るので、**引用パネルは常時表示**。開閉式にすると
使うたびに開く動作が挟まって邪魔になる。

```
┌─────────────────────────────────────────────────────────┐
│ 題：クリスチャンの断食について            [下書き] [公開範囲▾] │
├──────────────────────┬──────────────────────┤
│ 本文（書く）            │  引用パネル             │
│                       │  ┌──────────────┐   │
│  断食とは、霊的な目的の   │  │ お気に入り │ さがす │   │
│  ために食を断つことです。 │  └──────────────┘   │
│  [[matthew 6:16-18]]  │   書 → 章 → 節 と辿る      │
│                       │  ─────────────────  │
│                       │   マタイ 6:16                │
│                       │  「断食するときには…」        │
├──────────────────────┤   [文中に入れる][引用して入れる] │
│ プレビュー（見え方）      │  ─────────────────  │
│  断食とは…（マタイ6:16-18） │   マタイ 6:17 …          │
└──────────────────────┴──────────────────────┘
```

- 左を上下に割る。**プレビューは常に見えている**（印がどう見えるか確かめ続けるため）
- 引用パネルのタブは「お気に入り」と「さがす」の2つ。**さがすは、書→章→節と辿るのが主**。
  言葉での検索も置くが副
- 各節に2つのボタン。押すと**カーソルの位置に印が入る**
- 範囲は**2タップ**。節を押す→もう1つを「終わりに指定」で範囲になる。
  PCではドラッグでも取れるが、ドラッグ限定にはしない（スマホで使えなくなるため）
- 自動保存。`useAutosave.ts`（編纂で作ったもの）を流用
- スマホは1カラム。下のタブで 本文 / プレビュー / 引用 を切り替え
- **印の色分けは最初はやらない。** 入力欄では文字に色を付けられず、裏に色の層を
  重ねる自作の仕掛けが要る。まず色なしで書いてみて、辛ければ足す
- **画像は貼れない。** 本番（Render）ではサーバーに置いた画像が再デプロイで
  消える。外部の保存場所を用意する話は今回の範囲外

### 節のページ側

`CommentPanel.tsx` にタブを足す。

```
┌ マタイ 6:16 ─────────────────┐
│ コメント (3) │ 引用した記事 (2)      │
└──────────────────────┘
```

- デフォルトはコメント
- **記事が0件のときはタブごと出さない**（コメントだけの節はいまと同じ見た目）
- 節の行に件数の印は出さない（記事が増えてから考える）

### タグ

最初に15個用意する。

> 苦しみ / 死と復活 / 愛 / お金と施し / 祈り / 断食 / ゆるし / 律法 /
> 罪 / 救い / 終末 / 天使と悪魔 / 夢と幻 / 女性 / 食べもの

- 後から足せるのは管理者だけ（自由に打てると表記ゆれで散らかる）
- 1記事3つまで
- 0件のタグは一覧に出さない
- **「正典と外典」のような区分のタグは作らない。** `/read` から正典・外典の
  区分とラベルを消した経緯があり、タグで引き直すことになるため

### 公開まわり

- 公開 → 非公開に戻せる（コメントは残るが誰にも見えなくなる）
- 削除は本当に消える（コメントも一緒に）。確認ダイアログを出す
- 要約が空のままでは公開できない

### あとで決める

作りながら実物を見て決める。

- 「同じ主題の記事」を何件出すか
- 自分の記事にコメントが付いたときの通知（既存の通知を流用）
- 検索（`/search`）に記事を含めるか
- トップページからの導線
- 記事の長さ・引用の数の上限

## プラン

### データ

**Plan** — owner / title / description / **note（著者の注記）** / visibility

**PlanDay** — plan / 第N日 / title / **devotional（その日の文章）** / order

**PlanDayReading** — day / canonical_book / chapter_number / translation（任意）/ order

**PlanSubscription** — user / plan / started_at / 続けているか

**PlanDayProgress** — subscription / day / 読み終えた日時

### ルール

- **1日に章は10まで。プランは365日まで。**
- 単位は章（節ではない）。訳は任意で指定でき、**選ぶときは存在する訳だけ出す**
- 進捗は日ごとのチェックだけ。連続日数・通知は入れない
- 日付はプラン側に持たない。「第N日」の番号だけ持ち、始めた日から数えて画面に出す
- 途中でやめる／最初からやり直す ができる

### 編集できる範囲

| 状態 | できること |
|---|---|
| 下書き中 | 全部自由 |
| 公開したが、まだ誰も始めていない | 全部自由 |
| 1人でも読み始めた | 日の削除・並べ替えは不可／**末尾への追加は可**／日の中身（題・章の指定・文章）は全部修正できる |

進捗は「第N日」という番号に紐づくので、壊れるのは**日の順序が変わったときだけ**。
中身が変わっても進捗は壊れないので、誤りは直せるようにしておく。

**著者の注記は常に編集できる。** 構成を凍結する代わりに、
「第5日と第6日を入れ違えました」と書ける逃げ道を用意する。プランの冒頭に出す。

## 廃止するもの

- テーブル: `compiled_books` / `compiled_chapters` / `compiled_verses` / `compiled_comments`
  （`motif_tags` は記事のタグとして残す）
- 画面: `/compilations/*` すべて、トップページの編纂カード、ナビの導線
- `e2e/compilations.spec.ts`
- 本番のデータは、この削除をデプロイした時点で消える

**「集める」機能も廃止する。** あれは「どの編纂書に入れるか」を先に選ぶ必要が
あったから存在した。記事は書き始めてから引用を取りに行けるので、存在理由が消える。
溜める場所はお気に入りに一本化する（2か所あると「どっちに入れたか」が必ず起きる）。

ただし `CollectBar` の**複数の節をまとめて選ぶ操作はお気に入りへ移植する**。
読書中に3節まとめてお気に入りに入れられるのは便利なので。

参照用のコードはブランチ `codex/compiled-books`（コミット `3c4f40b`）に残してある。
