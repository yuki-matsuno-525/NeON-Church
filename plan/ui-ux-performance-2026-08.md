# UI/UX ・パフォーマンス改善（2026-08）

公開前の品質棚卸しとして、フロント（Next.js 16）とバックエンド（Django 5.2 / DRF）を
網羅的に調べ、見つかった問題を段階的に直した記録。

調査で見えた構造的な問題は3つだった。

1. **必要のないデータを大量に取っていた** — 「この節にお気に入りが付いているか」を知るためだけに
   その人のお気に入りを全件（最大1万件）落とし、章を1つ開くのに API を3回、順番待ちで叩いていた。
2. **サーバー側で1件あたり何回も問い合わせていた** — 通知20件で100〜200回、翻訳企画一覧20件で
   80回の追加問い合わせ。書を翻訳企画に追加すると1リクエストで約5000クエリ走っていた。
3. **失敗が利用者に伝わらなかった** — 投票・削除・お気に入り・編集保存という一番よく押すボタンが
   すべて無言で失敗し、通信エラーが「まだ何もありません」という空表示になっていた。

---

## 前提：main の取り込み

作業ブランチは `main` から分岐しており、「編纂(compilations) 廃止 → 記事(articles) 新設」
（`ae9234c`）が入っていなかった。先に `git merge main` してから着手した。
プロフィールページは両ブランチが同じ「もっと見る」を別々に実装していたため main 側を採用した。

## やったこと

### 速さ（フロント）

| # | 内容 | 効果 |
|---|------|------|
| A-1 | お気に入りの判定を箇所で絞って取る。`/api/bookmarks/` に `?book=&chapter=` `?translation_project=` を追加 | 章を開くたびの全件取得（最大1万件）が、その章の数件だけになる |
| A-2 | 章・書のページを1回の問い合わせに。`/api/references/<slug>/read/<章>/` と `.../book/` を追加 | 3往復の順番待ち → 1往復。書の全一覧を落として1冊探す無駄も消えた |
| A-3 | csrftoken の取得と認証確認を同時に投げる | 全ページで最初の表示が1往復ぶん速くなる |
| A-4 | 検索欄にデバウンス（300ms）。`useDebouncedValue` を追加 | 1文字ごとに 2〜3本飛んでいたリクエストが、打ち終わってから1回に |
| A-5 | Context 3つの値を `useMemo` 化。通知のポーリングはタブが裏なら止める | 未読数が変わるたびのアプリ全体の描き直しが止まる |

### 速さ（バックエンド）

| # | 内容 | 効果 |
|---|------|------|
| B-1 | 書の一括追加を `bulk_create` に | 詩篇で約5000クエリ → 3クエリ。`transaction.atomic()` も追加 |
| B-2 | コメントの書名の引き当てを1リクエスト内で使い回す | 20件のページで約160回 → 数回。Q&A・トレンド・検索・お気に入りにまとめて効く |
| B-3 | 通知の親コメント辿りを1回だけにし、親を2段先読み | 20件で100〜200回 → 十数回 |
| B-4 | 翻訳企画一覧の1件4クエリを `annotate` / `Exists` に | 20件で80回の往復が消える |
| B-5 | 上限のない一覧（企画コメント・メンバー・本棚・記事コメント）にページング | 1回のリクエストで無制限に返さない |
| B-6 | 複合索引を追加（通知・お気に入り・コメント・書） | `Meta.indexes` がプロジェクトに1つも無く、並び替えが件数に比例して重かった |
| B-7 | `CACHES` を明示。聖書本文の読み取り API に `Cache-Control` | 設定漏れで既定（プロセス内・300件・再起動で消滅）に落ちていた |
| B-8 | `STATICFILES_STORAGE` → `STORAGES` | Django 5.1 で削除済みの設定で、圧縮もハッシュ化も効いていなかった |
| B-9 | 記事コメントのビューが同じ記事を2回引いていたのを1回に | |

### 反応の伝え方

- **`error.tsx` を新設**。これが無かったため、描画中に1か所でも例外が出ると Next.js の
  既定エラー画面ごと落ち、戻ることも読み直すこともできなかった。
- **`loading.tsx` を主要ページに追加**。章のページは本文なので、節が並ぶ形にした。
- **握りつぶしていたエラーを表に出した**（投票・削除・お気に入り・編集保存・ベストアンサー・
  企画の公開切替・既読化）。既読化は失敗しても画面だけ既読になり未読数とずれていた。
- **通信エラーを「まだ何もありません」と言わなくした**。`useLoadMore` に「取りに行けなかったか」を
  持たせ、空とエラーで表示を分ける。
- **コメント削除に確認**を入れ、企画の公開切替などは処理中に押せないようにした。
  無効なボタンが押せそうに見えていた見た目も直した。

### スマホ・アクセシビリティ

- **読書画面の節をキーボードで選べるようにした**。節はただの `div` に `onClick` を
  付けただけで、キーボードだけの人はここで詰まり、その先のコメント・お気に入り・引用が
  丸ごと使えなかった。**この修正が今回いちばん影響が大きい。**
- **モーダルとサイドバー**を「開いたらそこだけ操作する」形にした（`useDialogBehavior`）。
  サイドバーは閉じていても画面外にあるだけでタブ順に残っていた。
- **入力欄の文字をスマホで16pxに底上げ**。iPhone は16px未満の入力欄をタップすると
  画面を勝手に拡大し、元の倍率に戻らない。
- **ラベルの無い入力欄9か所**に名前を付けた（読み上げでは「編集テキスト」としか伝わらなかった）。
- **`--text-faint` を 4.28:1 → 4.95:1** に。ホームの生の `rgba`（2.6〜4.0:1）もトークンへ。
- **`<html lang>` を表示言語に追随**。英語表示でも読み上げが日本語の発音になっていた。
- コメントパネルの高さを `vh` → `dvh`（スマホのアドレスバー伸縮でずれていた）。
- スマホのボタンの高さを44px以上に（返信・投票・お気に入り・削除が15〜32pxだった）。

### コードの整理

- テーマ切り替え（`next-themes` / `ThemeToggle`）を撤去。常にダーク固定で、
  ライトの配色も無く、押しても何も起きない部品だった。
- `src/types/api.ts`（2475行・未参照）、中身が空のフック、参照されていない
  `public/demo*.html` と `block-1.png`（956KB）を削除。
- 主ボタンのグラデーションが2か所に別々に書かれていたのを `--accent-primary-grad` に一本化。
- 見出しのフォント指定16か所が文字列の直書きで `next/font` の変数を通っていなかった。
- 全ページ共通の背景を CSS へ移動（読み込みの開始が早まる）。ホームが同じ背景を
  もう一枚重ねて描いていたのをやめた。
- ロゴを `next/image` に。画像に長期キャッシュのヘッダ。`optimizePackageImports` を追加。

## 確認したこと

- バックエンド `pytest`：517件パス / 13スキップ
- フロント `vitest`：297件パス
- 本番ビルド（`next build`）が通ることを確認（`optimizePackageImports` と `next/image` の検証）
- 型チェック（`tsc --noEmit`）とlintにエラーなし

追加したテストで、次のことが将来も壊れないようにしてある。

- お気に入りの箇所絞り込みが章のお気に入り・節のお気に入り・コメントのお気に入りをまとめて返し、他人のお気に入りは返さない
- 書・章・節が1回で揃い、「その訳に書が無い」と「章が無い」を言い分けられる
- 書の一括追加・企画一覧・通知一覧・Q&A一覧のクエリ数が、件数が増えても増えない
- 通信エラーが空表示にならない
- 節が Enter / Space で選べる、モーダルが Escape で閉じてフォーカスが外へ出ない

## 残していること

| 内容 | 理由 |
|------|------|
| 画像の再圧縮（`logo-og.png` 412KB → 184KB、`icon-512.png` 246KB → 131KB） | 256色に落とすと半分になるが、ネオン調のグラデーションが荒れないか目で見て確かめる必要がある |
| `src/app/demo/**`（約1300行）が本番ビルドに含まれる | デザインの試作として使っているかもしれないため、消すかどうかは要判断 |
| Redis の導入 | `REDIS_URL` を設定すれば切り替わるようにしてある。使うときは `requirements.txt` に `redis` を足す |
| 検索の1文字クエリ | trigram 索引は3文字未満で使えず全表走査になる。2文字未満を断るか `pg_bigm` を入れるかの判断が要る |
| `/api/search/` などのスロットル | 未認証で叩けて重い |
| フォームを `TextField` に寄せる | ラベル・エラー表示を持つ唯一の入力部品だが、まだデモページでしか使っていない |
| 画面を見ての確認 | この作業は worktree で行っており、Docker（localhost:3000）は main のコードを動かしている。タップ領域・コントラスト・背景まわりは実画面での確認が残っている |
